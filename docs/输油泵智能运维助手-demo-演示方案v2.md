# 输油泵智能运维助手 demo 演示方案 v2

> 面向业务方确认和 demo 开发使用。
> 本文用于确认 demo 定位、演示主线、AI / 模型 / 知识库介入点、页面建议、素材边界和定稿口径。

## 1. Demo 定位

本 demo 不是重做设备管理系统，也不是正式生产系统改造。

它要证明一件事：

```text
在现有“设备监测 -> 异常预警 -> 专业诊断 -> 专家复核 -> 检维修处置 -> 报告归档”的流程不变的前提下，
AI 可以辅助完成输油泵机组异常识别、诊断依据解释、处置知识命中、报告生成和案例复用，
让一次设备异常从“人工判断和材料归档”变成“模型诊断、知识支撑、人工确认、经验沉淀”。
```

首版 demo 的重点不是功能多，而是用一条可演、可讲、可指导开发的业务故事讲清楚 AI 赋能价值：

```text
长岭站 P-1 输油泵机组疑似不对中诊断与处置闭环。
```

首版必须保留两段演示：

```text
首次异常诊断闭环 + 第二次相似异常复用。
```

## 2. Demo 主骨架

推荐 demo 按下面骨架设计：

```text
设备运行数据
  -> 检测报告导入 / 趋势回放识别关注级诊断事件
  -> 专业诊断模型判断：疑似不对中
  -> 专家复核
  -> 知识库命中对中作业卡（标准模板卡，待业务确认适配 P-1）/ 历史经验
  -> Agent 生成处置建议和票卡草稿
  -> 现场处置与复测
  -> Agent 生成维修报告
  -> 案例入库
  -> 第二次相似异常命中复用
```

这条骨架嵌入现有设备运维流程，不改变“最终由专家和业务人员确认”的责任边界。

| 现有业务动作 | demo 新增辅助 | 人工仍需确认 | 本步输出 | 主要使用人 |
| --- | --- | --- | --- | --- |
| 设备运行监测 | 展示长岭站 P-1 输油泵机组振动、温度、压力、流量等关键数据 | 数据样例是否符合业务口径 | 设备状态卡、趋势曲线、状态分级 | 运维人员、设备管理人员 |
| 关注级诊断事件 | 基于检测报告导入或演示趋势回放，标记 P-1 振动关注项和状态等级变化 | 是否进入诊断流程 | 关注级诊断事件、异常测点 | 运维人员 |
| 专业诊断 | 诊断模型输出“疑似不对中”、风险等级、诊断依据 | 诊断结论是否需要专家复核 | 诊断结论卡、证据说明 | 设备专家、运维人员 |
| 专家复核 | 展示专家确认入口和复核意见 | 是否认可“疑似不对中”并进入处置 | 复核结论、处置触发条件 | 设备专家 |
| 知识命中 | 知识库命中对中作业卡标准模板、历史案例、专家经验规则 | 命中内容是否适配本设备 | 作业卡、处置建议依据、相似案例 | 设备专家、检维修人员 |
| 处置闭环 | Agent 生成处置票卡草稿、维修报告草稿 | 是否执行处置、复测结果是否合格 | 处置记录、复测结果、维修报告 | 检维修人员、管理人员 |
| 案例复用 | 第二次相似异常命中第一次沉淀案例 | 是否采纳复用建议 | 复用说明、相似案例推荐 | 运维人员、设备专家 |

## 3. AI / 模型 / 知识库介入点

首版不要求 AI 覆盖全部设备运维工作，只围绕 P-1 不对中主线做扎实。

| 能力 | 在 demo 中的作用 | 首版建议 |
| --- | --- | --- |
| 检测报告 / 趋势回放识别 | 从检测报告或演示趋势回放中识别 P-1 振动关注项，触发诊断入口 | 必做，用样例曲线、状态分级和异常特征讲清楚事件起点 |
| 专业诊断模型 | 判断“是什么问题”，输出异常类型、风险等级和诊断依据 | 必做，主结论为“疑似不对中” |
| 知识库 | 命中对中作业卡标准模板、诊断报告、历史经验和报告模板 | 必做，这是处置建议和案例复用的依据；作业卡需业务确认适配 P-1 |
| Agent 处置辅助 | 整理处置建议、票卡草稿、报告草稿、复用说明 | 必做，但限定在 P-1 不对中演示链路内 |
| 专家复核 | 把模型结论转成可进入处置的业务结论 | 必做，避免 demo 表达为模型自动定责或自动派工 |
| 案例入库与复用 | 把第一次诊断、处置、复测和报告沉淀成后续可命中的案例 | 必做，用于支撑第二次相似异常复用 |

### 3.1 专业诊断模型边界

诊断模型只负责“判断是什么问题”，不负责派工、办票、生成报告。

模型输出到这里为止：

```text
是否异常
异常类型
风险等级
证据匹配分值（演示值）
诊断依据
```

下面这些属于设备管理系统 + 知识库 + Agent：

```text
推荐作业卡
生成处置建议
生成票卡草稿
生成维修报告
案例入库复用
```

### 3.2 模型输入指标

| 输入指标 | 业务含义 | P-1 案例样例 |
| --- | --- | --- |
| 设备信息 | 哪台设备发生异常 | 长岭站 P-1 输油泵机组 |
| 测点信息 | 哪些位置出现异常 | 电机、泵、基础等测点 |
| 振动数据 | 异常程度和变化趋势 | 最大振动值 2.62mm/s |
| 状态分级 | 判断设备状态所用标准 | P-1 当前为 B 状态，良等级 |
| 诊断特征 | 支撑故障判断的特征 | 二倍频、相位差、多测点振动 |
| 辅助指标 | 帮助解释异常的其他数据 | 基础振动、温度、压力、流量等 |

### 3.3 模型输出指标

| 输出指标 | demo 展示口径 | P-1 案例建议 |
| --- | --- | --- |
| 是否异常 | 正常 / 异常 | 异常，但不表达为严重故障 |
| 异常类型 | 不对中、松动、轴承异常、工况偏离等 | 疑似不对中 |
| 风险等级 | 正常 / 关注 / 预警 / 严重 | 关注 |
| 证据匹配分值（演示值） | 0-100 演示分值 | 用于解释证据匹配，不代表线上模型概率输出 |
| 诊断依据 | 支撑判断的关键证据 | 二倍频成分、相位差、多测点振动 |

### 3.4 知识库最小集合

知识库不是“堆材料”，而是把材料整理成后续能命中的业务知识。

首版知识库建议准备最小集合：

```text
1 份 P-1 或同类输油泵诊断报告
1 份输油泵与电机对中作业卡标准模板，待业务确认适配 P-1
1 个维修报告模板
1 条 P-1 首次异常演示案例
1 组专家经验规则
```

| 文档类型 | 是否需要 | 需要整理的关键指标 |
| --- | --- | --- |
| 检测报告 / 诊断报告 | 需要 | 设备、异常现象、异常测点、诊断依据、故障类型、建议动作、结论 |
| 对中作业卡标准模板 | 需要，待业务确认适配 P-1 | 适用设备、适用故障、作业步骤、角色、工具、安全要求、验收项 |
| 维修报告模板 | 需要 | 报告章节、处置过程、复测结果、结论、审核角色 |
| 历史故障案例 | 建议 | 故障现象、原因判断、处理方式、处理效果、复用标签 |
| 专家经验规则 | 建议 | 触发条件、判断依据、建议先查什么、谁审核 |

### 3.5 P-1 对中作业卡落库指标

| 作业卡模块 | 可落库指标 |
| --- | --- |
| 前置条件 | 适用设备、适用故障、是否需要停机 / 隔离 / 许可 |
| 角色分工 | 检修负责人、作业人员、运行人员、监护人员 |
| 关键步骤 | 检修前记录、对中测量、调整、复测、恢复备用 |
| 安全要求 | 作业许可、风险分析、安全措施 |
| 验收结果 | 振动复测、试运行、签字关闭作业 |

### 3.6 支撑第二次复用的标签

| 复用标签 | P-1 案例建议 |
| --- | --- |
| 适用故障类型 | 不对中 |
| 适用症状 | 二倍频成分、相位差、多测点振动、基础振动偏大 |
| 适用设备范围 | 输油泵机组；同类泵 / 电机对中场景 |
| 前置条件 | 专家复核后进入处置；需要停机、隔离、作业许可和安全风险确认 |
| 推荐作业卡 | 输油泵与电机对中作业卡标准模板，待业务确认适配 P-1 |
| 预期效果 | 对中检查或调整后振动回落，设备恢复备用 |
| 复测验收 | 记录处置后振动和轴承温度，试运验收合格后关闭作业 |

## 4. 推荐演示故事

### 4.1 默认推荐故事

首版建议只讲一个主冲突：

```text
长岭站 P-1 输油泵机组在检测报告中出现关注级振动特征，
专业诊断模型判断为疑似不对中，
专家复核后进入对中检查 / 调整处置，
系统基于知识库生成处置建议和报告，
处置结果沉淀为案例，
第二次相似异常出现时可直接命中复用。
```

这个故事首版必须演清楚：

```text
模型判断“是什么问题”，
知识库说明“为什么这样处置”，
Agent 整理“怎么处置和怎么汇报”，
人工确认“是否采纳和是否闭环”，
案例复用证明“知识不是只归档”。
```

### 4.2 两段演示路线

#### 路线一：首次异常诊断闭环

```text
设备运行数据
  -> 检测报告导入 / 趋势回放识别关注级诊断事件
  -> 专业诊断模型判断：疑似不对中
  -> 专家复核
  -> 设备管理系统和知识库命中对中作业卡标准模板 / 历史经验
  -> 生成处置票卡和处置建议
  -> 现场处置反馈
  -> 生成维修报告
  -> 形成新案例入库
```

#### 路线二：第二次相似异常复用

```text
第二台同类设备出现相似异常
  -> 专业诊断模型判断：疑似不对中
  -> 知识库命中第一次沉淀的 P-1 案例
  -> 推荐相似处置经验和对中作业卡标准模板
  -> 输出复用说明
```

这两条路线要证明一件事：

```text
第一次能诊断、能处置、能沉淀；
第二次能复用，不是只把报告归档。
```

## 5. 推荐演示步骤

以下步骤可直接作为主持人讲解顺序，也可作为开发页面联调顺序。

```text
1. 打开“长岭站 P-1 输油泵机组”设备主页。
2. 展示设备基础信息、当前状态、振动趋势、温度 / 压力 / 流量等辅助指标。
3. 系统基于检测报告导入结果标记 P-1 关注级诊断事件，提示最大振动值 2.62mm/s，当前为 B 状态、良等级。
4. 点击进入异常事件，展示异常测点和趋势曲线。
5. 触发专业诊断模型，输出“异常，风险等级：关注，异常类型：疑似不对中”。
6. 展示诊断依据：二倍频成分、相位差、多测点振动、基础振动偏大。
7. 专家复核诊断结论，确认按疑似不对中进入处置建议环节。
8. 知识库命中“输油泵与电机对中作业卡”标准模板、相关诊断报告、专家经验规则，并提示该作业卡需业务确认适配 P-1。
9. Agent 生成处置建议：停机 / 隔离 / 作业许可确认，对中检查或调整，处置后复测。
10. 系统生成处置票卡草稿，展示角色分工、关键步骤、安全要求和验收项。
11. 人工录入或确认现场处置反馈，展示对中检查 / 调整结果和复测数据。
12. Agent 生成维修报告，包含异常现象、诊断依据、处置过程、复测结果和结论。
13. 系统将本次事件沉淀为“P-1 疑似不对中处置案例”，写入复用标签。
14. 切换到第二次相似异常，展示另一台同类设备出现二倍频、相位差、多测点振动等相似症状。
15. 专业诊断模型再次判断为“疑似不对中”。
16. 知识库命中第一次 P-1 案例，推荐相似处置经验、对中作业卡标准模板和复测验收要求。
17. 输出复用说明：本次建议参考 P-1 案例，但仍需专家复核和现场安全确认。
```

讲解时建议使用下面口径串联：

```text
前半段演示“发现问题到闭环处置”，
后半段演示“经验沉淀到相似复用”。
```

### 5.1 主持讲解与页面联调对照

这张表用于主持人彩排，也用于开发确认每个页面必须承载的讲点。

| 演示阶段 | 对应页面 | 主持讲解口径 | 要证明什么 |
| --- | --- | --- | --- |
| 设备进入视野 | 设备总览与诊断事件页 | “我们先从长岭站 P-1 的检测报告和趋势回放进入，不把 2.62mm/s 讲成实时报警，而是关注级诊断事件。” | 事件起点可信，不夸大报警口径 |
| 模型给出判断 | 专业诊断页 | “模型只判断是什么问题：当前状态 B、风险关注、疑似不对中，并展示二倍频、相位差、多测点振动等依据。” | 诊断不是黑盒，有证据链 |
| 人工把关 | 专业诊断页 | “模型结论进入专家复核，专家确认后才进入处置建议。” | AI 不替代专家责任 |
| 知识支撑处置 | 知识命中与处置建议页 | “知识库先命中 P-1 处置案例和诊断依据，再带出对中作业卡标准模板；作业卡是否适配 P-1 需要业务确认。” | 知识库不是资料堆放，且边界说清楚 |
| 形成处置材料 | 处置票卡与维修报告页 | “Agent 根据已确认结论和知识依据生成票卡草稿、处置建议和报告草稿，最终仍需人工确认。” | Agent 负责整理和成文，不自动派工审批 |
| 沉淀为案例 | 处置票卡与维修报告页 | “处置反馈、复测数据和报告结论会沉淀成结构化案例和复用标签。” | 报告不是终点，经验可沉淀 |
| 第二次复用 | 案例复用页 | “第二台同类设备出现相似症状时，系统命中 P-1 案例，给出相似处置经验，但仍提示专家复核和现场安全确认。” | 第一次经验能服务下一次异常 |
| 收束边界 | 案例复用页 | “首版不接生产系统、不做真实派工、不训练模型，只证明闭环和讲解路径成立。” | 范围可控，避免过度承诺 |

## 6. Demo 页面建议

首版页面控制在 5 个以内，避免把 demo 做成完整设备管理系统。

| 页面 | 展示内容 | 对开发的要求 | 边界 |
| --- | --- | --- | --- |
| 设备总览与诊断事件页 | 长岭站 P-1 设备卡、状态等级、振动趋势、关注级诊断事件、辅助指标 | 能一眼看到事件起点和设备上下文 | 不做全站设备资产管理 |
| 专业诊断页 | 模型输入、模型输出、诊断依据、风险等级、专家复核入口 | 模型结论和依据要能被讲清楚 | 不展示复杂训练过程 |
| 知识命中与处置建议页 | 命中作业卡标准模板、诊断报告、专家经验规则、相似案例 | 知识命中结果要能追溯到材料类型 | 不做开放式知识库问答 |
| 处置票卡与维修报告页 | 处置票卡草稿、现场反馈、复测数据、维修报告草稿 | 支持人工确认和报告生成演示 | 不做真实审批流和电子签章 |
| 案例复用页 | 第一次案例入库标签、第二次相似异常命中、复用说明 | 能对比“首次处置”和“二次复用” | 不做复杂知识图谱 |

页面之间建议按一条线跳转：

```text
设备总览与诊断事件页
  -> 专业诊断页
  -> 知识命中与处置建议页
  -> 处置票卡与维修报告页
  -> 案例复用页
```

## 7. 现有材料 / 素材支撑

结论：

```text
现有 P-1 诊断信息、模型输入输出口径、维修报告字段和复用标签，
已经足够支撑 demo 骨架、诊断展示、报告生成和案例复用。
对中作业卡可作为标准模板卡支撑处置建议和票卡草稿，但需要业务方确认其是否适配长岭 P-1。
如果业务方能补充真实趋势数据、真实报告样张和现场处置记录，演示可信度会更强。
```

现有材料可直接支撑的部分：

| demo 能力 | 现有材料 | 支撑情况 | 说明 |
| --- | --- | --- | --- |
| 设备异常主线 | 长岭站 P-1 输油泵机组疑似不对中案例口径 | 足够 | 可支撑“诊断事件 -> 诊断 -> 处置 -> 复用”的主故事 |
| 模型输入展示 | 设备信息、测点信息、振动数据、状态分级、诊断特征、辅助指标 | 足够 | 可支撑专业诊断页的输入区 |
| 模型输出展示 | 是否异常、异常类型、风险等级、证据匹配分值（演示值）、诊断依据 | 足够 | 可支撑诊断结论卡和解释区 |
| 知识库内容 | 诊断报告、对中作业卡标准模板、维修报告模板、历史故障案例、专家经验规则 | 基础足够，作业卡需确认适配 | 可拆成知识命中文档和 Agent 生成依据 |
| 处置票卡 | 前置条件、角色分工、关键步骤、安全要求、验收结果 | 需业务确认适配 | 可支撑票卡草稿页面，但不能直接说是 P-1 现成作业卡 |
| 案例复用 | 故障类型、症状、设备范围、前置条件、推荐作业卡、复测验收 | 足够 | 可支撑第二次相似异常命中 |

对业务方的建议口径：

```text
现有材料可以先开工搭 demo 骨架，不需要等待所有真实系统数据。
补充真实趋势、现场图片、处置记录和报告样张不是开工前提，
但会提升演示现场感和业务可信度。
```

## 8. 增强素材清单

| 素材 | 用途 | 首版处理方式 |
| --- | --- | --- |
| 1 组 P-1 振动趋势数据 | 增强异常曲线、阈值线、诊断触发点的现场感 | 没有真实数据时，使用业务认可的演示样例数据 |
| 1 组辅助运行数据 | 展示温度、压力、流量等辅助指标没有显著工况异常 | 没有真实数据时，只展示少量样例值 |
| 1 份真实或脱敏诊断报告 | 支撑诊断依据和报告生成内容 | 没有正式报告时，使用演示报告模板 |
| 1 份对中作业卡标准模板 | 支撑知识库命中和处置票卡生成 | 首版必须整理成结构化字段，并确认是否适配长岭 P-1 |
| 1 条现场处置反馈记录 | 支撑“处置后复测、恢复备用、报告归档” | 没有真实记录时，使用业务确认的演示记录 |
| 1 个第二次相似异常样例 | 支撑案例复用页面 | 可构造为同类泵 / 电机对中场景，但症状标签要与 P-1 案例一致 |

建议裁定：

```text
如果业务方只确认当前 P-1 案例口径：
  可以做“诊断模型 + 知识库命中 + 处置建议 + 报告生成 + 案例复用”的完整闭环。

如果业务方再补 1 组真实趋势数据：
  诊断触发和模型输入展示会更贴近现场。

如果业务方确认现有作业卡模板适配 P-1，或补充 P-1 适配版作业卡和报告样张：
  知识库命中、票卡生成和报告生成会更有说服力。
```

## 9. 业务方需要确认的事项

业务方主要确认“主线是否成立、输入输出是否认可、素材是否可提供、边界是否接受”。技术实现方式由 demo 方案确定，不要求业务方判断模型细节。

| 确认项 | 默认方案 | 需要业务方给出的结论 |
| --- | --- | --- |
| 主线故事 | 长岭站 P-1 输油泵机组疑似不对中诊断与处置闭环 | 是否接受 P-1 作为首版唯一主线 |
| 两段演示 | 首次异常诊断闭环 + 第二次相似异常复用 | 是否认可“第一次沉淀、第二次复用”的演示结构 |
| 模型输入 | 设备、测点、振动、状态分级、诊断特征、辅助指标 | 输入指标是否完整，样例值是否符合业务口径 |
| 模型输出 | 是否异常、异常类型、风险等级、证据匹配分值（演示值）、诊断依据 | 是否按“异常但不严重，风险等级关注，疑似不对中”展示；证据匹配分值不代表线上模型概率 |
| 知识库范围 | 诊断报告、对中作业卡标准模板、维修报告模板、历史案例、专家经验规则 | 是否认可首版最小知识库范围 |
| 作业卡适配 | 现有作业卡是标准模板卡，设备型号与 P-1 检测报告不完全一致 | 是否接受按标准模板卡演示，或提供 P-1 适配版作业卡 |
| 作业卡内容 | 前置条件、角色分工、关键步骤、安全要求、验收结果 | 作业卡字段是否适配现场作业要求 |
| 复用标签 | 故障类型、症状、设备范围、前置条件、推荐作业卡、预期效果、复测验收 | 标签是否足够支撑第二次相似异常命中 |
| 增强素材 | 趋势数据、辅助指标、报告样张、处置反馈、第二次异常样例 | 哪些素材可提供真实或脱敏版本 |

默认已经定下的内容：

```text
演示设备默认选长岭站 P-1 输油泵机组。
异常类型默认选疑似不对中。
风险等级默认按“关注”展示。
知识库默认覆盖诊断报告、对中作业卡标准模板、维修报告模板、历史案例和专家经验规则；作业卡需业务确认适配 P-1。
Agent 默认只做处置建议、票卡草稿、维修报告草稿和复用说明。
```

除非业务方明确要求替换，否则不再扩大首版范围。

## 10. 首版边界

首版 demo 控制在演示态，不做生产系统能力。

| 不做项 | 对业务方的说明 |
| --- | --- |
| 不接真实设备管理系统、PI、DCS 或振动监测平台 | 先用样例数据和演示事件把闭环讲清楚 |
| 不做现场模型训练 | 首版只展示诊断模型输入输出和结论解释，不演训练过程 |
| 不自动替代专家诊断 | 模型给出疑似结论，专家复核后进入处置 |
| 不自动派工和审批 | 只生成处置票卡草稿，不接正式流程 |
| 不做全类型故障诊断 | 首版只围绕疑似不对中，不扩展到轴承、松动、汽蚀等完整故障库 |
| 不做全设备资产管理 | 只展示 P-1 和第二次相似异常所需的同类设备样例 |
| 不做开放式通用问答 | Agent 只围绕本次异常、作业卡、报告和案例复用回答 |
| 不做完整知识图谱 | 只做最小知识库和复用标签，支撑演示链路 |

## 11. 推荐定稿口径

这个 demo 演什么：

```text
演示 AI 如何嵌入输油泵智能运维流程，
从长岭站 P-1 输油泵机组关注级诊断事件出发，
由专业诊断模型判断疑似不对中，
通过专家复核和知识库命中形成处置建议，
由 Agent 生成处置票卡和维修报告，
再把处置结果沉淀为案例，
用于第二次相似异常复用。
```

这个 demo 不演什么：

```text
不演正式系统接入，
不演全量故障诊断，
不演模型训练过程，
不演真实派工审批，
不演模型自动替代专家判断，
不演开放式通用 Agent。
```

业务方现在只需要确认什么：

```text
是否接受长岭站 P-1 疑似不对中作为首版主线；
是否接受“首次闭环 + 二次复用”的两段演示；
模型输入输出和风险等级口径是否认可；
对中作业卡标准模板、维修报告模板、案例标签是否可以作为知识库最小集合；
是否接受现有作业卡作为标准模板卡适配 P-1，或需要补充 P-1 适配版作业卡；
哪些真实或脱敏素材可以补充用于增强演示可信度。
```

确认后首版能看到什么：

```text
一套可点击、可演示、能讲完整业务闭环的 demo：
诊断事件、专业诊断、专家复核、知识命中、处置建议、票卡草稿、维修报告、案例入库、相似异常复用。
```
