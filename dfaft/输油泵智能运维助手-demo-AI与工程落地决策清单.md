# 输油泵智能运维助手（"泵智护"）demo AI 与工程落地决策清单

> 文档性质：demo 开发前工程边界确认表（需求会配套决策材料）
> 配套主文档：[《输油泵智能运维助手-demo-业务架构与实施蓝图.md》](./输油泵智能运维助手-demo-业务架构与实施蓝图.md)
> 使用方式：主文档用于讲业务闭环；本文用于逐项确认 AI、模型、数据、接口、知识库、智能体等工程落地方式。

---

## 1. 文档目标

本文不是技术详设，也不是开发任务清单，而是 demo 开工前必须和业务方确认的工程决策清单。

业务方材料里出现了"AI 架构、WeAgent、数智员工、智能体、大模型、深度模型、工艺参数时序库、知识库、知识图谱、无线探测器、六大系统打通"等词。这些词不能被自动理解为首版都要真实建设，也不能被简单忽略。它们要被逐项判断：

- 材料有没有明确提到；
- 对 demo 主闭环是否必要；
- 首版推荐做到什么深度；
- 不推荐什么；
- 业务方必须确认什么；
- 如果坚持升级，会怎样影响报价、工期和风险。

【建议】开会时先用主文档确认"预警 → 诊断 → 处置 → 报告 → 知识回流"闭环，再用本文逐项拍板 AI 与工程落地方式。

## 2. 一句话结论

【建议】首版 demo 不应默认建设完整 AI 平台、深度模型、知识图谱、时序数据平台、视觉模型或真实多系统接口，也不应把真实大模型调用作为基线硬前提。首版应采用：

```text
真实做：
  频谱/多参数研判逻辑
  小型故障特征库和案例库
  限定范围的数智员工引导
  报告生成
  三端任务闭环

演示数据：
  关键设备智能监测平台、IMS、PI、供应链、HSE、PPS

预留升级：
  真实大模型调用
  集团私有化模型/WeAgent 平台接入
  真实系统接口
  深度模型训练
  知识图谱
  无线传感器接入
  正式时序数据模型

明确排除首版：
  YOLO / 视觉模型
  原生 App
  自建完整智能体平台
  开放式 Agent
  具体模型名绑定
```

## 3. 工程边界拍板总表

主方案第 10 节冻结"demo 做什么业务范围"；本节冻结"这些工程项做到什么深度"。两者并列进入会议纪要：主方案定业务基线，本文定工程边界。后文的 AI、大模型、时序、YOLO、知识库、智能体等技术项，都服务于本表的拍板项。

| # | 决策项 | 默认结论【建议】 | 材料触发依据 | 业务方选择 | 变更影响 | 会后动作 |
|---:|---|---|---|---|---|---|
| 1 | 交付形态与验收口径 | 可交互模拟 PoC；验收按"一条主线跑通 + 3 个自由交互点" | 材料承诺模拟数据可完整演示全业务流程（申报书 §1.3/团队优势） | 认可 / 升级为半真实集成 / 升级为试点 MVP | 一旦升级，接口、环境、测试、验收全部上浮 | 会议纪要冻结验收口径 |
| 2 | 主线故障剧本 | 只做 1 条主线，轴承故障或不对中二选一 | 材料强调预警、诊断、溯源、工单、报告、知识回流闭环（申报书 §2.2） | 轴承故障 / 不对中 / 其他 | 每增一条剧本，新增数据、规则、页面联调 | 指定业务专家审定剧本 |
| 3 | AI 诊断深度 | 频谱特征 + 阈值/统计规则 + 多参数趋势 + 案例匹配 | 材料有振动频谱、阈值分析、深度模型，也承认历史故障数据库严重缺失（申报书 §1.1/§2.1） | 规则研判 / 训练模型 | 训练模型需样本、标签、评测集、专家标注，单独报价 | 明确 90%+ 是目标值还是验收值 |
| 4 | AI 输出责任边界 | AI 给疑似故障、排查方向、报告初稿；专家最终确认 | 材料设置诊断专家端并要求专家评判发布报告（申报书 §2.1/§2.2） | 专家确认 / AI 自动闭环 | 若 AI 自动闭环，需责任归属、审计日志、合规机制 | 冻结"AI 辅助，不替代专家"口径 |
| 5 | 数据来源与脱敏授权 | 优先使用通用模拟数据集；波形、案例、模板由业务方提供并签认脱敏 | 材料承诺通用模拟数据集可演示；申报材料含真实性与合规承诺 | 业务方提供 / 技术方构造 | 拿不到数据则技术方构造样例，报价上浮，需专家签认 | 列出数据交付人、字段、时间点 |
| 6 | 真实系统集成深度 | 关键设备智能监测平台、IMS、PI、供应链、HSE、PPS 全部用演示数据；只做字段联动 | 材料提六大系统打通，同时承诺无需外部场站资源即可演示（申报书 §1.3/§2.1） | 演示数据 / 真实只读 / 真实写入 | 每接一个真实系统都增加接口、权限、联调、安全审批 | 确认首版不碰生产读写 |
| 7 | 是否真实调用大模型 | 不作为首版基线硬前提；有现成通道时，只用于报告初稿和解释话术 | 材料有数智员工、WeAgent；PPT 原件第 16 页按主方案转述出现"智能体与大模型技术" | 不调用 / 调用外部 API / 调用集团模型 | 真实调用增加账号、网络、合规和现场稳定性验证；无通道不影响主闭环 | 冻结"模型不承担诊断结论" |
| 8 | 是否接集团私有化底座 / WeAgent 平台 | 不默认接平台；若演示必须内网或必须体现集团底座，单独确认接入条件 | 材料有国产化私有化底座、私有化内网、WeAgent 和数智员工（申报书 §3.1/团队优势） | 不接平台 / 接集团底座 / 接 WeAgent | 平台接入增加权限、配额、网络、联调和现场验证 | 确认演示环境和平台责任人 |
| 9 | 时序数据范围 | 只做 72 小时演示级时序样例；不建正式时序数据平台 | 材料有工艺参数时序库、PI、温度、压力、阀位、流量、电流（申报书 §2.1） | 演示样例 / 正式模型 | 正式时序模型涉及采集、存储、质量规则和治理 | 业务方提供 PI 字段样例与单位 |
| 10 | 知识沉淀范围 | 小型故障特征库、案例库、作业卡/报告模板；报告发布后回写一条记录 | 材料明确有运维知识库、知识图谱、故障案例库、一机一档（申报书 §2.2/§2.3） | 小库 / 知识问答 / 图谱引擎 | 知识问答、图谱、自进化模型均为升级项 | 提供 5-10 条案例和模板 |
| 11 | 终端形态 | 三端 Web 视图；作业区端做移动端样式页，不做原生 App | 材料写作业区端通过移动端接收作业卡并反馈，未写原生 App（申报书 §2.1） | 移动样式页 / 原生 App | 原生 App 增加打包、安装、真机测试、移动能力验收 | 确认真机演示是否必须 |
| 12 | 视觉模型边界 | YOLO/视觉模型不做 | 材料未提图像、视频、摄像头、视觉识别、YOLO | 不做 / 新增视觉 | 视觉模型是独立数据采集、样本标注和模型项目 | 若新增，另起需求和报价 |
| 13 | 硬件接入边界 | 无线传感器不接入 demo | 无线振动/温度探测器属于监测盲区治理（申报书 §2.1） | 不接硬件 / 接硬件 | 硬件接入涉及站点、协议、网络、安全和安装条件 | 若新增，按现场试点评估 |
| 14 | 首版范围红线 | 不做深度模型训练、真实生产系统接口读写、原生 App、无线传感器硬件接入、知识图谱引擎、Skill 正式纳入集团 AI 能力库、开放式 Agent、1558 台全量覆盖 | 材料目标是大赛演示和后续推广，不等同首版全部建设 | 冻结 / 放开 | 不冻结会导致范围蔓延、报价失真 | 写入会议纪要和报价前提 |

## 4. 工程术语取舍表

| # | 工程项 | 材料是否提到 | 首版是否必要 | 推荐结论【建议】 | 业务方必须确认 |
|---:|---|---|---|---|---|
| 1 | 是否真实接 AI API / 大模型 | "大模型"来自 PPT 原件和主方案转述；申报书有数智员工、WeAgent | 可选 | 首版基线不依赖真实模型；如有通道，可用于报告生成和解释文本；不能作为核心诊断唯一依据 | 是否有集团私有化模型通道、是否允许外部 API、是否必须离线 |
| 2 | 是否接集团数智员工底座 / WeAgent | 材料明确出现"WeAgent 智能体"和"集团统一数智员工底座" | 需确认 | 首版表现为限定流程助手；是否真实接平台由业务方确认 | WeAgent 是否可给 demo 使用、账号/权限/接口/配额是否具备 |
| 3 | 是否建设智能体平台 | 材料有"智能体工作流" | 不必要 | 不自建完整平台；只做可演示的任务引导和流程编排 | 是否要求接现有平台，还是只要求演示效果 |
| 4 | 是否做开放式 Agent | 材料未明确要求开放式 Agent | 不必要 | 不做；首版限定意图、限定流程、限定工具 | 是否接受限定交互，是否有现场自由问答需求 |
| 5 | 是否设计时序数据模型 | 材料有"工艺参数时序库"、PI、振动/温度/压力/电流 | 需要演示级设计 | 做演示级时序样例和字段口径；不建设正式时序数据平台 | 是否提供 PI 样例字段、频率、时间范围、单位、脱敏要求 |

| 7 | 是否训练深度模型 | 材料有深度模型，但也说历史故障数据库严重缺失 | 不做首版 | 首版预留模型位，正式项目再训练 | 是否有历史故障样本、标签、专家标注和评测口径 |
| 8 | 是否做 YOLO / 视觉模型 | 材料未提图像、视频、视觉识别、YOLO | 不做 | 不纳入首版，不写入报价基线 | 业务方若坚持，需另提供视觉场景、样本、摄像头和验收指标 |
| 9 | 是否建设知识库 | 材料明确出现运维知识库、故障案例库、典型故障特征库 | 必要 | 做小型结构化知识库，支撑案例匹配和报告沉淀 | 业务方能否提供案例、作业卡、报告模板和专家审核 |

| 11 | 是否接真实六大系统接口 | 材料提到关键设备智能监测平台、IMS、PI、供应链、HSE、PPS | 不做首版基线 | 首版使用演示数据；真实接口作为升级项 | 哪些系统允许只读、哪些绝不允许写入、是否有测试环境 |

## 5. 逐项决策口径

### 5.1 真实 AI API / 大模型

| 项 | 结论 |
|---|---|
| 材料依据 | PPT 原件第 16 页按主方案转述出现"智能体与大模型技术"；申报书多次出现"数智员工"和"WeAgent 智能体" |
| 材料是否明确要求真实 AI API | 未明确。材料没有写具体模型名、API 形式、调用通道或配额 |
| 首版推荐 | 【建议】首版基线不依赖真实模型；如业务方确认已有可用通道，可作为增强用于报告生成、排查解释、话术润色；诊断结论仍由频谱/规则/案例支撑 |
| 不推荐 | 不推荐把大模型作为故障诊断唯一依据；不推荐承诺开放式问答 |
| 升级条件 | 业务方提供集团私有化模型通道、账号、配额、网络环境和数据合规口径 |
| 报价影响 | 若接集团底座，增加联调和环境验证；若外部 API 禁用且需本地部署，单独报价 |

会议提问：

```text
Q：demo 是否接受"不依赖真实模型"作为首版基线？
Q：如果必须真实调用模型，使用集团私有化底座、外部 API，还是本地部署？
Q：模型输出是否只用于报告和解释，不用于最终故障结论？
```

### 5.2 WeAgent / 数智员工 / 智能体平台

| 项 | 结论 |
|---|---|
| 材料依据 | 申报书写到"WeAgent 智能体自动完成跨系统数据清洗与关联分析"；材料多次描述数智员工参与故障排查、报告生成和系统拉通 |
| 材料是否明确要求搭建智能体平台 | 没有。材料提到智能体和工作流，但没有说明要新建平台 |
| 首版推荐 | 【建议】做"限定流程数智员工"：预警后引导排查、关联案例、生成建议、生成报告 |
| 不推荐 | 不推荐首版自建完整智能体平台；不推荐开放式 Agent 自主调用多工具 |
| 升级条件 | 确认集团 WeAgent/数智员工底座是否可接入 demo，以及是否允许调用系统数据 |
| 报价影响 | 接现有平台需要联调；自建平台属于正式项目级工作 |

会议提问：

```text
Q：业务方说的 WeAgent 是必须真实接入，还是 demo 中表现为数智员工流程即可？
Q：数智员工的边界是辅助建议，还是能自动派单、自动更新系统？
Q：现场是否允许自由问答？如果允许，问题范围是什么？
```

### 5.3 时序数据模型 / PI / 工艺参数

| 项 | 结论 |
|---|---|
| 材料依据 | 材料提到"工艺参数时序库"、PI 系统、温度、压力、阀位、流量、电流，以及振动波形频谱 |
| 材料是否要求正式时序数据平台 | 没有。材料要求对接 PI 和多源参数，但未要求 demo 建正式时序库 |
| 首版推荐 | 【建议】做演示级时序样例：一台主角机组、72 小时时间轴、若干关键参数曲线 |
| 不推荐 | 不推荐首版设计生产级时序数据模型、采集链路、存储策略和数据治理体系 |
| 升级条件 | 提供 PI 字段表、采样频率、时间范围、单位、质量码、缺失值规则和脱敏样本 |
| 报价影响 | 正式时序模型涉及数据治理、接口、存储、性能和质量规则，需单独评估 |

会议提问：

```text
Q：PI / 工艺参数数据是否能提供样例？
Q：demo 只需要 72 小时回放，还是需要任意时间查询？
Q：频谱波形和工艺参数是否需要严格时间对齐？
```

### 5.4 视觉模型 / YOLO

| 项 | 结论 |
|---|---|
| 材料依据 | 未发现图像、视频、摄像头、视觉识别、YOLO 等材料依据 |
| 材料是否要求 | 未要求 |
| 首版推荐 | 【建议】不纳入首版，不进入报价基线 |
| 不推荐 | 不推荐为了"AI 感"额外加入视觉模型 |
| 升级条件 | 业务方新增明确视觉场景，如仪表识别、跑冒滴漏识别、现场作业行为识别，并提供样本和验收指标 |
| 报价影响 | 视觉模型是独立数据采集和模型项目，会显著增加周期、样本、标注和现场风险 |

会议提问：

```text
Q：材料没有视觉场景，业务方是否确认首版不做 YOLO/视觉模型？
Q：如果业务方新增视觉诉求，是为了哪一个业务动作服务？
```

### 5.5 知识库 / 故障案例库 / 典型故障特征库

| 项 | 结论 |
|---|---|
| 材料依据 | 材料明确提出运维知识库、典型故障特征库、故障案例库、一机一档和报告自动更新至知识库 |
| 材料是否要求 | 明确要求知识沉淀，但未明确首版规模 |
| 首版推荐 | 【建议】做小型结构化知识库：故障类型、特征、案例、排查步骤、作业卡、报告模板 |
| 不推荐 | 不推荐首版承诺知识库自进化效果；不推荐做泛化知识问答 |
| 升级条件 | 业务方提供真实案例、作业卡、报告模板、专家审核机制和知识分类规则 |
| 报价影响 | 知识整理和专家确认是主要工作量；若要求问答检索或知识治理，单独报价 |

## 6. 首版推荐组合

## 8. 报价与工期影响口径

| 升级项 | 影响 | 会议口径 |
|---|---|---|
| 真实大模型调用 | 增加模型账号、网络、数据合规和现场稳定性验证 | "首版基线不依赖真实模型；没有可用通道不影响主闭环演示。" |
| 集团私有化底座 / WeAgent 平台接入 | 增加平台权限、配额、接口联调、内网部署和现场验证 | "是否接集团底座是单独决策，不等于材料提到数智员工就默认可接。" |
| 自建智能体平台 | 从 demo 变成平台建设 | "材料提到智能体，不等于首版要自建平台。" |
| 正式时序数据平台 | 增加数据建模、采集、存储、质量规则 | "首版只需要 72 小时演示级样例。" |
| YOLO / 视觉模型 | 增加样本、标注、训练、现场摄像头 | "材料未提视觉场景，不进入基线。" |
| 知识图谱 | 增加实体关系建模和图谱治理 | "首版先证明知识沉淀，不证明图谱推理。" |
| 深度模型训练 | 增加数据治理、标注、训练、评测 | "材料承认历史故障库缺失，训练不能默认包含。" |
| 真实系统接口 | 增加跨部门协调、权限、联调、安全审批 | "申报书已承诺模拟数据可完整演示，真实接口是升级项。" |
| 原生 App | 增加移动开发、真机测试和安装分发 | "移动端演示视图已足够证明现场执行闭环。" |
| 硬件传感器 | 增加采购、安装、协议、网络、现场安全 | "硬件补盲属于试点项目，不属于大赛 demo。" |
