**一、几条业务线分别是什么意思**

**1. 泵机组大修**

```text
预测性维修 / 项修建议
  -> 审查计划建议
  -> IMS 资产完整性计划
  -> 大修方案编制与审批
  -> 年度作业计划
  -> 物料准备
  -> 现场作业准备
  -> 现场大修
  -> 大修作业完成
  -> IMS 履历更新
  -> 知识库更新
```

这条线偏“重维修、大周期、审批和物料多”，适合正式项目，不适合首版 demo 主线。

**2. 泵机组集中监测诊断管理**

```text
监测平台发现异常
  -> IMS 事件中心
  -> 数智员工查故障知识库
  -> 推荐原因 / 排查方向 / 相似案例
  -> 逐条排查
  -> 判断能否确定故障原因
  -> 专家确认
  -> 现场维检修准备
  -> 工单 / 作业卡 / 备件 / HSE / PPS
  -> 维修完成
  -> 报告生成
  -> 知识库更新
  -> 举一反三经验复用
```

这是**最适合首版 demo 的主线**，因为它能一次讲清预警、诊断、知识库、人工确认、处置、报告、复用。

**3. 泵机组日常巡检管理**

```text
制定巡检策略
  -> 组织巡检
  -> 巡检发现问题
  -> IMS 事件中心
  -> 数智员工辅助描述问题
  -> 查知识库给排查建议
  -> 专家确认 / 现场排查
  -> 维检修
  -> 报告
  -> 知识库更新
```

它适合作为扩展入口。首版可以露出“日常巡检”菜单，但不建议完整展开。

**4. 泵机组计划性维护保养（4K）**

```text
PPS / IMS 运行时间
  -> 统计累计运行时间
  -> 智能体提醒 4K 保养
  -> 生成年度作业计划
  -> 物料准备
  -> 现场维护保养
  -> 维护报告
  -> IMS 履历更新
  -> 知识库更新
```

这是计划型维护，不是异常触发，戏剧张力弱一些。适合后续扩展。

**5. 泵机组项修**

```text
储运技术公司提出项修建议
  -> 审查计划建议
  -> IMS 资产完整性计划
  -> 项修方案编制与审批
  -> 年度作业计划
  -> 物料准备
  -> 现场项修
  -> 项修完成
  -> IMS 履历更新
  -> 知识库更新
```

项修和大修类似，偏方案、审批、物料和周期，不适合 15 天 demo 主线。

**6. 输油泵机组仪表点位图**

它不是流程线，是 demo 的“设备证据素材”。

```text
输油泵设备图
  -> 标出温度、振动、压力等测点
  -> demo 中高亮异常点位
  -> 说明异常发生在哪个部件 / 模块
```

它应该放在“设备详情页”，用于增强可信度。

**二、参赛主题图给 demo 的启发**

WeACT 这几张图不是输油泵业务流程，而是参赛主题方向：

```text
数智员工赛道：
  AI 驱动核心业务高效运转

桌面办公助手赛道：
  AI 处理重复性工作，提高效率

深度研究 / 知识引擎赛道：
  把分散资料、经验、制度沉淀成可复用知识资产
```

对本项目的启发是：

```text
demo 不要做成普通监测大屏
也不要做成聊天机器人
而要做成：
  AI / 数智员工推动业务闭环
  企业知识库提供依据
  处理结果沉淀为知识
  下次相似问题可以复用
```

**三、首版 demo 应该怎么落地**

建议首版只做：

```text
主线：
  泵机组集中监测诊断管理

其他业务线：
  首页露入口，作为后续扩展，不完整展开
```

首版演示闭环：

```text
首页风险设备
  -> 设备详情和异常点位
  -> 趋势异常
  -> 知识库命中案例 / 作业卡 / 风险要求
  -> 数智员工给排查建议
  -> 专家确认或疑难接管
  -> 生成处置任务
  -> 作业反馈
  -> 报告预览
  -> 知识沉淀
  -> 相似异常复用提示
```

**四、是否采纳 `dfaft/12.md` 里的技术路线**

可以采纳，但建议作为**内部实现路线**，不要直接写给业务方。

你列的这套很适合做定制 demo：

```text
React / Vue 前端
mock JSON 数据
React Flow 流程图
图表库做趋势曲线
知识命中卡片
工单状态流转
报告预览
复用验证卡片
```

落到页面上就是：

```text
React Flow：
  展示预警 -> 研判 -> 处置 -> 报告 -> 复用的流程

图表库：
  展示 72 小时趋势曲线、振动/温度/压力变化

mock JSON：
  存设备、测点、案例、作业卡、工单、报告模板

知识命中卡片：
  展示相似案例、标准作业卡、HSE 风险要求

工单状态流转：
  待确认 -> 待处置 -> 处理中 -> 已反馈 -> 已闭环

报告预览：
  展示异常事件分析报告

复用验证卡片：
  模拟下一次相似异常命中本次经验
```

**五、最终判断**

```text
业务主线：
  选集中监测诊断管理

演示方式：
  定制 demo，不接真实系统

数据方式：
  预置演示数据

知识库方式：
  做知识命中和引用依据展示，不做真实 RAG

闭环重点：
  不能只到报告，要到知识沉淀和下次复用

技术路线：
  可以内部采用 React/Vue + mock 数据 + 流程图 + 图表 + 卡片式演示
  但对业务方只说“定制演示 demo”，不要锁死技术栈
```

一句话：**业务上只演“集中监测诊断”一条完整闭环；技术上用定制前端演示系统最快、最稳；其他业务线只做扩展入口，避免 demo 变成大而全。**
