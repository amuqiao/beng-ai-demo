有，但**没有一个开源项目能直接等同于“输油泵智能运维助手 demo”**。更现实的做法是参考几个开源项目的“演示形态”，然后组合成你自己的前端 demo。

我建议按这几类参考。

## 1. 设备 / 工单 / 运维闭环参考

**Atlas CMMS**
适合参考：设备台账、工单、维护任务、库存、报表、移动端维护管理。它是开源 CMMS，定位就是设备维护管理系统，包含工单、设备、库存、工作流、报表等能力。([github.com](https://github.com/grashjs/cmms?utm_source=openai))

可以借鉴到你的 demo：

```text
设备详情
工单状态
备件需求
处置任务
维护记录
报表统计
```

**Shelf.nu**
适合参考：设备资产管理、位置、责任人、二维码、维护提醒、审计记录。它更偏资产 / 设备管理，不是故障诊断，但设备台账和履历页面有参考价值。([github.com](https://github.com/shelf-nu/shelf.nu?utm_source=openai))

可以借鉴到你的 demo：

```text
一机一档
设备履历
设备状态
维护提醒
责任人 / 位置 / 标签
```

## 2. RAG / 企业知识库展示参考

**kotaemon**
适合参考：知识库问答、文档检索、引用依据展示。它是开源 RAG 工具，重点是“和文档对话”。([github.com](https://github.com/Cinnamon/kotaemon?utm_source=openai))

**rag-web-ui**
适合参考：知识库管理、文档上传、RAG 问答、引用来源、多模型部署选项。([github.com](https://github.com/rag-web-ui/rag-web-ui?utm_source=openai))

**OpenDocuments**
适合参考：企业文档搜索、带引用的 AI 检索、跨知识源整合。([github.com](https://github.com/joungminsung/OpenDocuments?utm_source=openai))

但你的首版 demo 不建议真的接这些系统。只参考它们的展示方式：

```text
命中相似案例
引用作业卡
引用风险要求
显示依据来源
报告中标注参考依据
```

## 3. 流程图 / 闭环可视化参考

**React Flow**
适合做你的“业务闭环图”“处置流程图”“知识流转图”。它是开源 React 节点图组件，适合做可点击流程节点、状态流转、业务关系图。([reactflow.dev](https://reactflow.dev/?utm_source=openai))

可以用于：

```text
预警 -> 研判 -> 复核 -> 处置 -> 报告 -> 沉淀 -> 复用

IMS / HSE / PPS / 供应链关系示意

知识库命中路径
```

这个对你的 demo 很有价值。

## 4. 维护任务看板参考

**shadcn Maintenance Kanban block**
适合参考：维护任务从 Scheduled、In Progress、Completed 的状态流转，带优先级、类型、批量操作。([shadcn.io](https://www.shadcn.io/blocks/kanban-maintenance-log?utm_source=openai))

可以借鉴到你的 demo：

```text
待确认
待处置
处理中
待报告
已闭环
```

## 我的建议

你的 demo 最像下面几类的组合：

```text
设备资产管理页面
  参考 Shelf.nu

工单 / 维护闭环
  参考 Atlas CMMS

知识库 / RAG 命中
  参考 kotaemon / rag-web-ui / OpenDocuments

流程可视化
  参考 React Flow

任务状态看板
  参考 shadcn Maintenance Kanban
```

但不要直接套完整开源项目。你现在更适合做一个**定制前端演示系统**：

```text
React / Vue 前端
mock JSON 数据
React Flow 流程图
图表库做趋势曲线
知识命中卡片
工单状态流转
报告预览
复用验证卡片
```

一句话结论：

**有参考项目，但没有现成项目直接匹配。最值得参考的是 Atlas CMMS 的运维闭环、RAG Web UI/kotaemon 的知识依据展示、React Flow 的流程可视化。你的 demo 应该做成定制前端演示，而不是二开某个完整系统。**
