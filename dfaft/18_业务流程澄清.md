## A. 监测诊断类

### 图里出现的能力

```text
监测诊断大模型
机组健康评估模型
机理模型
异常趋势 / 预警
振动、温度、压力等测点数据
```

### demo 里建议怎么演

```text
展示一台泵出现异常趋势：
  某个测点异常
  趋势曲线变化
  系统产生预警事件
  进入设备详情页
```

### 需要业务方确认

| 问题 | 为什么要问 |
|---|---|
| 首版异常场景选哪类？异常振动、轴承异常、不对中、温度异常，还是其他？ | 决定主线故事 |
| 异常测点是哪一个？对应仪表点位图里的哪个点？ | 决定设备详情页怎么高亮 |
| 是否需要展示 72 小时趋势？ | 决定趋势数据怎么构造 |
| 需要展示哪些指标？振动、温度、压力、电流？ | 决定图表字段 |
| 诊断结论要写成什么口径？“疑似原因”还是“确定故障”？ | 避免 AI 过度承诺 |
| 是否需要展示频谱图？ | 决定是否加频谱视觉效果 |

### 不要猜的点

```text
不要默认就是轴承故障。
不要默认需要频谱图。
不要默认 AI 能直接确定原因。
```

## B. 知识库 / RAG 类

### 图里出现的能力

```text
故障溯源知识库
历史故障案例
标准化维检修知识库
作业卡 / 指导书
作业风险知识库
技术通告
报告内容更新知识库
```

### demo 里建议怎么演

```text
预警后点击“查找依据”
  -> 命中相似案例
  -> 命中作业卡
  -> 命中风险要求
  -> 每条排查建议显示引用依据
```

### 需要业务方确认

| 问题 | 为什么要问 |
|---|---|
| 知识库里希望展示哪几类知识？案例、作业卡、风险要求、技术通告？ | 决定知识命中卡片 |
| 相似案例能否提供 1-3 条脱敏样例？ | 决定 demo 可信度 |
| 作业卡 / 指导书是否有模板？ | 决定处置建议怎么写 |
| 风险要求来自哪里？HSE？作业风险知识库？ | 决定风险提示口径 |
| demo 里叫“RAG”还是叫“企业知识库查找依据”？ | 决定业务方能不能听懂 |
| 知识入库是否需要专家审核？ | 决定是否做“确认入库”按钮 |
| 知识沉淀后，下一次怎么复用？ | 决定复用验证场景 |

### 不要猜的点

```text
不要默认知识库是真实 RAG。
不要默认报告自动入库不需要审核。
不要默认案例、作业卡、风险要求都齐全。
```

| IMS 履历更新展示哪些字段？ | 决定一机一档更新效果 |

### 特别需要问清楚：PPS 是什么

```text

demo 中需要展示哪些字段？
```

### 不要猜的点

```text
不要默认 HSE 是某一种固定票。
不要默认 PPS 是某一种事件。
不要默认备件一定要展示采购和出库。
```

```text
  现场记录
```
