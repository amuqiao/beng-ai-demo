你这个问题很关键。前面我说“一套演示数据”，表达得太抽象了。

它的意思不是让业务方去理解“数据工程”，而是：

```text
demo 要能演起来，必须提前准备一批“演示用素材”。
这些素材就是 demo 里的道具。
没有这些道具，页面就只能是空壳。
```

换个说法：

```text
演示数据 = demo 剧本里的业务材料 + 页面里展示的内容 + 点击后出现的结果
```

它和 demo 的关系是：

```text
没有演示数据：
  页面能打开，但没有可信内容
  数智员工没有案例可关联
  工单没有内容可生成
  报告没有依据可展示
  知识沉淀没有东西可回流

有演示数据：
  demo 才能从“页面展示”变成“业务故事”
```

**举个具体例子**

假设 demo 主线是：

```text
某站 2# 输油泵出现异常趋势
  -> 系统预警
  -> 数智员工辅助分析
  -> 专家复核
  -> 作业处置
  -> 报告生成
  -> 知识沉淀
```

那就必须提前准备这几个“故事道具”：

```text
1. 这台泵是谁？
   站场名称
   设备编号
   型号
   投运时间
   历史维修记录

2. 它为什么报警？
   最近 72 小时振动趋势
   温度变化
   压力变化
   电流变化
   某个时间点触发预警

3. 系统怀疑什么故障？
   疑似轴承早期劣化
   或疑似不对中
   或疑似振动异常

4. 为什么这么判断？
   有一条相似历史案例
   有一个参数异常说明
   有一段专家建议

5. 接下来怎么处理？
   检查项目
   作业卡
   工单内容
   所需备件
   作业区反馈

6. 最后沉淀什么？
   一份报告
   一条案例记录
   一条一机一档履历
```

所以我前面列的东西，对应关系是这样的：

```text
设备台账
  = demo 里的“这台泵是谁”

趋势数据
  = demo 里的“它为什么报警”

故障案例
  = demo 里的“以前有没有类似问题”

作业卡
  = demo 里的“现场人员按什么步骤排查”

工单
  = demo 里的“这个任务怎么派发、怎么跟踪”

报告模板
  = demo 里的“最后生成什么报告”

知识库样例
  = demo 里的“这次经验怎么沉淀”
```

**用业务话讲**

不要跟业务方说：

```text
请提供一套演示数据
```

这个说法太技术、太泛。

应该说：

```text
为了把 demo 演成一个完整故事，
我们需要提前确定一台主角设备、一段异常趋势、一个典型故障场景、
一条相似历史案例、一套作业处置步骤、一份报告样例。
```

这就好懂了。

**更准确的表达应该是**

```text
demo 演示素材包
────────────────
1. 主角设备
   用来说明“这次异常发生在哪台泵上”

2. 异常趋势
   用来说明“为什么系统会提前预警”

3. 典型故障场景
   用来说明“系统怀疑的故障是什么”

4. 相似历史案例
   用来说明“为什么这个判断可信”

5. 作业处置步骤
   用来说明“现场人员接下来怎么处理”

6. 处置反馈
   用来说明“作业区如何完成闭环”

7. 报告样例
   用来说明“系统最后能生成什么成果”

8. 知识沉淀样例
   用来说明“这次处置如何变成可复用经验”
```

这才是对业务方更合适的说法。

**和 demo 每一步的关系**

```text
首页态势
  需要：主角设备 + 背景设备

预警触发
  需要：异常趋势

智能诊断
  需要：典型故障场景 + 相似历史案例

专家复核
  需要：诊断依据 + 专家建议

作业处置
  需要：作业处置步骤 + 工单样例

移动端反馈
  需要：处置反馈样例

报告生成
  需要：报告样例

知识回流
  需要：知识沉淀样例
```

你可以把它重新讲成：

```text
demo 不是先要一堆“数据表”，
而是需要一套能支撑演示故事的业务素材。

这套素材要回答：
  谁出问题？
  为什么预警？
  怀疑什么故障？
  有什么依据？
  怎么处理？
  谁来反馈？
  生成什么报告？
  沉淀什么经验？
```

**最终建议改口径**

以后不要说：

```text
一套演示数据
```

改成：

```text
一套 demo 演示素材包
```

业务方更容易理解。

完整说法是：

```text
为了保证 demo 能稳定演示，我们建议先和业务方共同确定一套“演示素材包”：
一台主角输油泵、一段异常趋势、一个典型故障场景、一条相似案例、
一套处置步骤、一份报告样例和一条知识沉淀样例。
这些内容不要求一开始都来自真实系统，可以先用脱敏样例或业务专家确认过的演示内容。
```

这和 demo 的关系就是：

```text
演示素材包 = demo 能讲成业务故事的基础
```

你这个质疑是对的，之前“设备台账、趋势数据、故障案例”这种说法偏技术，应该改成“主角设备、异常趋势、典型故障场景、相似案例、处置步骤、报告样例、知识沉淀样例”。
