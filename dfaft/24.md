你可以这样问业务方，直接发：

```text
我这边想确认一下“专业诊断模型”在 demo 里的表达口径，避免我们把模型能力讲偏。

以长岭 P-1 不对中这个案例为例，模型本身是不是只负责输出类似下面这类结果：

1. 是否异常：正常 / 异常；
2. 异常类型：不对中、松动、轴承异常、工况偏离、仪表异常等；
3. 风险等级：正常 / 关注 / 预警 / 严重；
4. 异常评分或置信度：比如 0-1 或 0-100；
5. 诊断依据：比如 2X 频谱、相位差、多测点振动等。

然后模型输出以后，再由 IMS / 知识库智能体去做后续动作：
- 命中历史案例；
- 推荐对中作业卡；
- 生成处置建议；
- 派发检修任务；
- 回填维修结果；
- 生成报告；
- 入库复用。

也就是说，我们想把 demo 拆成两层来设计：

第一层：专业诊断模型负责“判断是什么问题”；
第二层：知识库 + IMS 流程负责“这个问题怎么处理、怎么闭环”。

这样理解对不对？
如果你们已有专业诊断模型或算法模块，也请帮忙确认一下它的输入和输出字段，哪怕是大概口径也可以。
```

更短一点可以发：

```text
想确认一下，demo 里的“专业诊断模型”是不是只负责输出：是否异常、故障类型、风险等级、异常评分和诊断依据？后面的作业卡推荐、派工、报告、知识入库，是 IMS + 知识库智能体负责的业务流程。这样拆分对不对？
```

这个问法比较稳，不会显得你不懂模型，也不会逼业务方回答“时序模型还是自研模型”这种他们可能也说不清的问题。
