# 03. 知识库与复用闭环

> 本文负责：定义企业知识库 / RAG 在 demo 中的表达方式、命中逻辑、案例入库和复用验证。  
> 本文不负责：真实 RAG 引擎、真实向量数据库、真实大模型 API。  
> 关键口径：知识库不是为了“归档报告”而存在，而是贯穿诊断解释、处置建议、报告生成和下次复用。

## 首版表达方式

首版用“可视化知识命中”表达知识库智能体能力：

```text
诊断模型输出故障类型、证据标签、建议动作
  -> 知识库命中作业卡、专家规则、历史案例、报告模板
  -> 辅助专家复核和现场处置
  -> 处置完成后生成新案例
  -> 下次相似异常命中新案例并推荐同类处置
```

这不是黑盒问答，也不是开放式聊天。首版重点是让业务看清楚“命中了什么、为什么命中、推荐什么”。

## 知识内容

| 知识类型 | 内容 | 样例来源 | 用途 |
|---|---|---|---|
| 标准作业卡 | 对中作业步骤、角色、工具、许可、验收项 | P1 对中作业卡抽取 | 生成处置票卡 |
| 专家规则 | 2X 频谱 + 相位异常 + 基础振动 -> 优先检查对中 | P1 报告和专家口径抽取 / 演示构造 | 解释诊断依据 |
| 历史案例 | 同类泵不对中或振动异常案例 | 历史报告素材可整理，首版可构造 | 支撑相似案例命中 |
| 报告模板 | 事件概况、诊断依据、处置过程、复测结果、经验标签 | 历史报告抽取 / 业务待补 | 生成报告草稿 |
| 新入库案例 | P1 本次诊断和对中处置结果 | demo 主线形成 | 下次复用验证 |

## 首次知识命中

输入：

```text
fault_type = misalignment_suspected
evidence_tags = 2X频谱 / 相位差异常 / 基础振动偏大
asset_tags = 长岭站 / 输油泵机组 / P1
action_tags = 检查对中
```

输出：

| 命中对象 | 命中理由 | demo 展示 |
|---|---|---|
| 对中作业卡 | 建议动作包含“检查对中” | 作业卡卡片 |
| 专家规则 | 证据组合符合不对中排查逻辑 | 规则解释卡 |
| 历史相似案例 | 故障标签和证据标签相似 | 相似案例卡 |
| 报告模板 | 处置闭环需要形成标准报告 | 报告模板卡 |

## 入库时机

P1 新案例不是一开始就存在，它在闭环结束后生成：

```text
现场反馈完成
  -> 报告草稿生成
  -> 专家确认报告
  -> 知识审核通过
  -> P1 案例进入演示知识库
```

入库内容至少包括：

| 内容 | 说明 |
|---|---|
| 故障标签 | 不对中、2X 频谱、相位差、基础振动 |
| 诊断证据 | 趋势、频谱、相位、阈值 |
| 处置动作 | 对中检查、调整、复测 |
| 处置结果 | 振动回落、恢复备用 |
| 复用建议 | 下次同类异常优先检查对中 |

## 复用验证

复用验证用第二台相似异常证明知识库不是静态归档：

```mermaid
flowchart LR
  A["P1 案例已入库"] --> B["第二台相似异常"]
  B --> C["诊断模型输出相似证据标签"]
  C --> D["知识库命中 P1 案例"]
  D --> E["推荐同类排查路径"]
  E --> F["推荐对中作业卡"]
```

复用成立的标准：

| 验证点 | 标准 |
|---|---|
| 命中新案例 | 第二台相似异常命中 P1 新案例 |
| 命中理由清楚 | 展示同类标签和证据标签 |
| 推荐动作可执行 | 推荐检查对中和调取对中作业卡 |
| 不重复主线 | 尾段不再完整生成处置票卡和报告 |
