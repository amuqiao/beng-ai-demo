# 输油泵智能运维助手 demo AI 赋能演示定稿方案

本文是输油泵智能运维助手 demo 的当前对外方案，用于业务沟通、立项汇报、参赛演示范围确认和验收口径确认。

它不负责技术栈、数据契约、接口设计、部署方式和开发顺序；这些内容分别维护在 [输油泵智能运维助手-demo-技术实施定版方案](输油泵智能运维助手-demo-技术实施定版方案.md) 和 [输油泵智能运维助手-demo-开发指导](输油泵智能运维助手-demo-开发指导.md)。

## 0. 结论速览

### demo 心智模型

这个 demo 不是把巡检质量分析换成泵设备页面，也不是做一个输油泵资产管理大屏。它要演示的是：AI 如何嵌入输油泵智能运维流程，把一次关注级异常从发现、诊断、处置、报告，推进到案例沉淀和下次复用。

核心闭环：

```text
监测数据形成异常事件
  -> 诊断模型输出疑似故障和证据标签
  -> 专家复核确认边界
  -> 知识库命中作业卡、专家规则、历史案例和报告模板
  -> Agent 辅助生成处置建议、票卡草稿和报告草稿
  -> 现场反馈和复测验收
  -> 案例入库
  -> 第二台相似异常复用验证
```

首版主故事固定为：

```text
长岭站 P-1 输油泵机组
  -> 关注级振动异常事件
  -> 专业诊断结论：疑似不对中
  -> 证据标签：2X 频谱、相位差异常、基础振动偏大
  -> 专家确认进入处置
  -> 命中对中作业卡和专家规则
  -> 生成处置票卡和维修报告草稿
  -> 复测验收后沉淀 P-1 案例
  -> 长岭站 P-2 相似异常命中 P-1 案例并推荐复用
```

一句话口径：

```text
首版 demo 不证明生产系统已经全部建成，
而是证明输油泵智能运维助手可以围绕一台泵、一次异常、一次处置和一次复用，
把监测诊断、专家把关、知识依据、标准作业和经验沉淀讲成一条闭环。
```

### 与巡检 demo 的差异

巡检 demo 的主轴是多区域、多检查项、多模态质检：

```text
巡检任务
  -> 区域表单
  -> 表单 / 时序 / 视觉疑点
  -> 复检确认
  -> 报告归档
```

输油泵 demo 的主轴是单设备、强诊断、标准处置和经验复用：

```text
设备异常
  -> 专业诊断
  -> 证据链解释
  -> 专家复核
  -> 知识命中
  -> 处置票卡
  -> 复测报告
  -> 案例复用
```

因此首版不按多个泵区、巡检区、保养区并列铺开，而是把 P-1 疑似不对中这条闭环讲透。

## 2. 先定性质

业务申报材料覆盖远程监测诊断、巡检管理、维护检修、项修、大修等完整愿景，但首版 demo 不能把这些都做成并列页面。首版定位为 `开发前冻结的参赛 / 立项演示 PoC`，不是生产系统、试点 MVP 或集团级推广平台。

| 层级 | 适合当前 demo 吗 | 处理方式 |
| --- | --- | --- |
| 参赛 / 立项演示 PoC | 适合 | 用固定结构化样例跑通 P-1 异常诊断处置和 P-2 复用验证。 |
| 试点 MVP | 下一阶段 | 需要真实接口、权限、审计、部署、角色和试点验收。 |
| 正式项目 / 区域推广 | 不适合作为首版 | 需要多设备、多故障、多系统协同和运维制度配套。 |

首版业务痛点压缩成一句话：

```text
监测数据、诊断依据、作业卡、专家经验和维修报告都有材料，
但一次异常从发现到复用仍需要人工跨材料串联。
```

demo 要证明的是：

```text
AI 可以把离散监测数据转成可解释诊断，
把诊断结论转成有依据的处置动作，
把处置反馈转成报告和可复用案例。
```

### 2.1 申报能力映射

首版只演 P-1/P-2 两个样例，不代表只覆盖单案例价值。它用一条闭环压缩展示申报材料中的远程监测诊断、三级体系和知识沉淀能力。

| 申报能力 | 本 demo 证明点 | 对应演示职责 | 本次不展开部分 |
| --- | --- | --- | --- |
| 远程监测诊断 | P-1 关注级异常由趋势、阈值、频谱、相位证据支撑，并输出疑似不对中诊断。 | 主事件入口、诊断解释 | 不接真实实时监测接口，不训练真实诊断模型。 |
| 后端：储运技术公司诊断预警 | 诊断证据和专家复核负责把异常转成专业结论。 | 诊断解释、复核和知识依据 | 不模拟真实组织审批和专家排班。 |
| 中端：区域监视中心 / 分控中心 | 关注级事件在 IMS 模块内被接收、解释，并推进到处置建议。 | 主事件入口、复核和知识依据、处置和复测 | 不接真实集中监视平台告警流。 |
| 前端：作业区现场执行 | 处置票卡、现场反馈和复测验收证明建议能落到现场动作。 | 处置和复测 | 不做真实派工、移动端执行和 HSE 办票。 |
| 知识沉淀迭代 | P-1 报告确认、知识审核后形成案例，P-2 相似异常可命中复用。 | 报告和复用 | 不做完整知识图谱、真实 RAG 或全故障库。 |

答辩口径：

```text
P-1 不是孤立脚本，而是把申报方案中的监测诊断、三级角色协同、
标准处置和知识沉淀压缩到一条可演示闭环里。
P-2 复用验证负责证明这条闭环不是一次性报告，而是可沉淀、可复用的组织经验。
```

## 3. 核心演示主线

定版主线：

```text
P-1 主事件入口
  -> P-1 关注级异常事件
  -> 一泵一档和测点证据
  -> 趋势、频谱、相位解释
  -> 诊断模型输出疑似不对中
  -> 专家复核
  -> 知识库命中
  -> 处置票卡
  -> 现场反馈和复测
  -> 维修报告
  -> 案例入库
  -> P-2 相似异常复用验证
```

推荐演示故事：

```text
长岭站 P-1 出现振动趋势异常，
系统在 IMS 数据中台智能运维 demo 模块中形成关注级诊断事件。
诊断节点结合趋势、频谱和相位证据，输出疑似不对中结论。
专家复核后，知识库命中对中作业卡、专家规则、历史案例和报告模板。
Agent 根据已确认结论和命中依据生成处置建议、处置票卡草稿和维修报告草稿。
现场反馈和复测通过后，本次闭环沉淀为 P-1 不对中处置案例。
随后 P-2 出现相似异常，系统命中刚刚沉淀的 P-1 案例并推荐同类处置经验。
```

## 4. AI 插点和能力映射

不要从“训练什么模型”开始讲，而要从输油泵运维闭环讲 AI 放在哪里。

| 流程节点 | AI 赋能点 | 首版做法 |
| --- | --- | --- |
| 异常事件形成 | 从监测数据回放中标记关注级异常 | 使用结构化演示数据和预置事件，不接真实实时接口。 |
| 专业诊断 | 把趋势、频谱、相位转成疑似故障和证据标签 | 使用预置诊断输出 + 可解释证据链。 |
| 专家复核 | 将模型结论交给专家确认或驳回 | 页面提供复核状态和意见，不替代专家。 |
| 知识命中 | 命中作业卡、专家规则、历史案例、报告模板 | 使用可视化命中卡和命中理由。 |
| 处置建议 | 根据确认结论和知识依据生成处置建议 | Agent 只整理已确认材料，不做真实审批。 |
| 处置票卡 | 生成 IMS 演示态处置票卡 | 展示角色、许可、工具、步骤和反馈入口。 |
| 报告生成 | 汇总事件、证据、处置、复测和经验标签 | 使用模板生成报告草稿和确认状态。 |
| 案例复用 | 第二台相似异常命中新案例 | 展示相似标签、复用内容和人工边界。 |

## 5. 首版范围

首版只做可演示的最小闭环。

| 能力 | 页面表现 | 首版实现深度 |
| --- | --- | --- |
| 设备与异常事件 | P-1 主事件入口、一泵一档、P-1 关注事件 | 结构化演示数据，不接真实系统。 |
| 趋势与测点证据 | 振动趋势、阈值线、异常测点高亮 | 预置曲线和阈值口径。 |
| 频谱与相位解释 | 1X / 2X / 6X、相位差、证据标签 | 预置特征，不展示训练过程。 |
| 诊断结果 | 疑似不对中、关注级、建议动作 | 预置诊断输出 + 解释链。 |
| 专家复核 | 复核意见、确认进入处置 | 人工确认是必要边界。 |
| 知识命中 | 作业卡、专家规则、历史案例、报告模板 | 最小知识集合和命中理由。 |
| 处置票卡 | 对中作业步骤、许可、工具、反馈入口 | 演示态票卡，不做真实派工审批。 |
| 现场反馈 | 调整记录、复测数据、验收结论 | 可用演示构造数据，但必须标注。 |
| 报告和入库 | 维修报告草稿、案例标签、知识审核确认 | 模板报告，不替代正式发布。 |
| 复用验证 | P-2 命中 P-1 案例 | 尾段价值收束，不再展开第二次完整处置。 |

页面控制在 5 个以内，精确页面名称和顺序只维护在 [演示路线与页面交互方案](输油泵智能运维助手-demo-演示路线与页面交互方案.md)。对外沟通只保留页面职责边界：

| 页面职责 | 展示什么 | 不做什么 |
| --- | --- | --- |
| 异常入口 | P-1 主事件卡、P-1 设备状态、异常测点、关注级事件 | 不做全设备资产管理平台。 |
| 诊断解释 | 趋势、阈值、频谱、相位、疑似不对中结论 | 不展示真实模型训练或开放推理。 |
| 复核和知识依据 | 复核意见、作业卡、专家规则、历史案例、报告模板 | 不做开放式知识问答。 |
| 处置和复测 | 处置步骤、许可字段、现场反馈、复测验收 | 不做真实 HSE 办票和供应链联动。 |
| 报告和复用 | 维修报告、知识审核、P-2 相似异常复用 | 不做全故障库和全生命周期平台。 |

## 6. 必须保留、可以简化、不做

### 6.1 必须保留

| 能力 | 原因 |
| --- | --- |
| P-1 疑似不对中主线 | 让首版有一个具体、专业、可闭环的业务故事。 |
| 趋势、频谱、相位证据 | 体现泵课题区别于巡检表单质检的专业诊断深度。 |
| 专家复核 | 保持安全生产和诊断责任边界。 |
| 知识命中 | 证明建议不是凭空生成，而是来自作业卡、规则、案例和模板。 |
| 处置票卡和现场反馈 | 把诊断推进到可执行处置，不停留在图表和结论。 |
| 报告生成、知识审核和案例入库 | 证明过程资料经人工审核后沉淀为组织经验。 |
| P-2 复用验证 | 证明知识库不是静态归档，而是能服务下一次相似异常。 |

### 6.2 可以首版简化

| 能力 | 简化方式 |
| --- | --- |
| 诊断模型 | 使用预置输出和可解释证据链，不训练真实模型。 |
| 时序数据 | 使用演示趋势和少量关键点，不做完整历史数据回放。 |
| 知识库 | 用可视化命中卡表达，不接真实向量库或真实 RAG。 |
| Agent | 只生成处置建议、票卡草稿、报告草稿和复用说明，不做开放问答。 |
| HSE / 供应链 | 只在票卡里展示许可、JSA 或备件字段，不宣称真实联动。 |
| 第二次复用 | 只展示命中 P-1 案例和推荐动作，不重复完整闭环。 |

### 6.3 首版不做

| 不做项 | 原因 |
| --- | --- |
| 不接真实 IMS / PI / HSE / PPS / 供应链接口 | 会变成系统集成项目，权限、网络、联调和审计不可控。 |
| 不训练真实诊断模型 | 需要长期历史数据、故障标签、评测集和专家标注。 |
| 不接真实大模型或真实 RAG 引擎 | 首版验收需要输出稳定可控。 |
| 不覆盖不对中、轴承、不平衡、泄漏、启泵失败等全类型故障 | 首版先把 P-1 一条闭环讲透。 |
| 不做日常巡检、计划保养、项修、大修全流程 | 这些是后续业务线，不进入首版主线。 |
| 不做真实派工审批、HSE 办票、采购库存联动 | 涉及生产流程、权限、审计和责任边界。 |
| 不做 AI 自动替代专家判断 | 诊断、处置、报告和入库都保留人工确认。 |
| 不做完整知识图谱 | 首版只展示命中依据、案例入库和复用验证。 |

## 7. 业务方需要确认的 8 件事

| 确认项 | 推荐默认 | 影响 |
| --- | --- | --- |
| 首版主线 | 长岭站 P-1 疑似不对中 | 决定整个演示故事是否锁定。 |
| 风险等级 | 关注级诊断事件 | 避免讲成严重事故或实时生产报警。 |
| 诊断依据 | 2X 频谱、相位差异常、基础振动偏大 | 决定证据链是否可讲。 |
| 阈值口径 | B 级、停机值 7.1、80% 预警线 5.68 按演示口径标注 | 决定趋势图和风险等级表达。 |
| 对中作业卡 | 作为标准模板卡，待业务确认适配 P-1 | 决定处置票卡可信度。 |
| 处置后复测数据 | 可先用演示构造，需标注 | 决定闭环和报告真实感。 |
| 报告模板 | 默认六段式维修报告 | 决定报告预览格式。 |
| 复用样例 | 长岭站 P-2 相似异常演示样例 | 决定复用页是否成立。 |

确认后冻结 `演示数据包`、`诊断证据口径`、`作业卡模板口径`、`报告模板` 和 `演示脚本`。冻结后新增内容按变更处理。

## 8. 冻结项和验收口径

| 冻结项 | 验收方式 |
| --- | --- |
| 主故事 | 能完整讲出 P-1 首次闭环和 P-2 复用验证。 |
| 页面范围 | 5 个页面以内，每页承担一个清晰讲点。 |
| 结构化数据 | 页面运行时读取结构化演示数据，不直接读取 Word / Excel / 图片。 |
| 诊断证据 | 趋势、阈值、频谱、相位能支撑疑似不对中表达。 |
| 人工边界 | 诊断、处置、报告、入库都有人工确认点。 |
| 知识复用 | P-2 相似异常只能在 P-1 报告确认、知识审核通过后命中 P-1 案例，并展示命中理由。 |
| 生产边界 | 不宣称真实系统接入、真实模型训练、真实审批或专家替代。 |

## 9. 责任边界

| 问题 | 定稿口径 |
| --- | --- |
| 诊断结论是谁给的 | demo 中呈现诊断模型输出和专业证据，但专家确认后才进入处置。 |
| Agent 是否能自动派工 | 不能。Agent 只整理已确认结论和知识依据，生成草稿和建议。 |
| 作业卡是否正式适配 P-1 | 首版讲成标准模板卡，是否正式适配需业务确认。 |
| 复测数据是否真实 | 可使用真实、脱敏或演示构造数据；演示构造必须标注。 |
| P-2 是否真实事故 | 可作为复用验证样例；若为演示构造，不讲成真实历史事件。 |

## 10. 会上可以这样说

### 10.1 开场

```text
这次我们不做一个大而全的输油泵平台，
而是用长岭站 P-1 的一次关注级诊断事件，
讲清楚智能运维助手如何把异常发现、专业诊断、专家复核、标准处置、报告沉淀和下次复用串成闭环。
```

### 10.2 解释诊断模型

```text
这里不是让模型凭空给结论。
页面同时展示趋势、阈值、频谱和相位证据，
模型输出只是把这些结构化证据组织成“疑似不对中”的诊断建议，
最终仍由专家复核确认。
```

### 10.3 解释知识库和 Agent

```text
知识库负责说明依据来自哪里，
包括对中作业卡、专家规则、历史案例和报告模板。
Agent 不替人审批，只把已确认的诊断结论和知识依据整理成处置建议、票卡草稿和报告草稿。
```

### 10.4 解释复用价值

```text
第一次 P-1 异常闭环后，系统不仅生成报告，
还把证据、处置、复测和专家意见沉淀成案例。
第二台相似异常出现时，可以直接命中这条案例，推荐同类排查路径。
```

## 11. 后续路线

| 阶段 | 建议扩展 |
| --- | --- |
| 首版 demo | P-1 疑似不对中闭环 + P-2 复用验证。 |
| 试点 MVP | 接入真实 IMS / 监测数据、角色权限、审计和真实报告模板。 |
| 诊断扩展 | 增加轴承磨损、不平衡、机械密封泄漏、启泵失败等故障类型。 |
| 业务扩展 | 扩展到日常巡检、计划维护、项修、大修周期预测。 |
| 集团推广 | 多站点、多品牌、多故障知识库和标准化作业体系。 |
