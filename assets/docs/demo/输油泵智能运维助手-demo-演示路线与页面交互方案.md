# 输油泵智能运维助手 demo 演示路线与页面交互方案

本文是输油泵智能运维助手 demo 的当前演示蓝图，用于指导页面设计、演示走查、素材挂载和主持讲解。

它不维护技术实现细节和字段枚举；技术边界见 [输油泵智能运维助手-demo-技术实施定版方案](输油泵智能运维助手-demo-技术实施定版方案.md)，字段和 JSON 样例见 [../../v1/demo-研发基准/05-结构化数据契约.md](../../v1/demo-研发基准/05-结构化数据契约.md)。

## 1. 本次要达成的目标

演示目标不是展示一个完整输油泵管理平台，而是让观众在 8 到 12 分钟内看懂一条闭环：

```text
P-1 为什么被关注
  -> 为什么诊断为疑似不对中
  -> 谁确认进入处置
  -> 处置建议依据是什么
  -> 现场处理后如何证明闭环
  -> 报告和案例如何沉淀
  -> P-2 相似异常如何复用 P-1 经验
```

页面设计必须服务这条线。任何页面如果不能回答这条线上的一个问题，就不进入首版。

## 2. 演示心智模型

巡检 demo 是“从一轮巡检任务中发现疑点”；泵 demo 是“从一个关键设备异常中完成诊断处置”。页面结构因此不按区域切换，而按闭环节点推进：

```text
异常入口
  -> 证据解释
  -> 人工复核
  -> 知识和处置
  -> 报告和复用
```

推荐固定 5 页：

```text
P-1 主事件入口
专业诊断与证据链
专家复核与知识命中
处置票卡与复测反馈
报告归档与案例复用
```

## 3. 推荐演示路线

### 3.1 标准路线

```text
首页进入 P-1 关注事件
  -> 点击异常测点
  -> 查看趋势、阈值、频谱、相位
  -> 展示疑似不对中诊断结果
  -> 专家确认进入处置
  -> 知识库命中对中作业卡和专家规则
  -> Agent 生成处置建议和票卡草稿
  -> 填写现场反馈和复测结果
  -> 生成维修报告草稿
  -> 确认案例入库
  -> 切到 P-2 相似异常复用验证
```

### 3.2 主持讲解节奏

| 时间 | 内容 | 讲解重点 |
| --- | --- | --- |
| 0:00-1:00 | P-1 主事件入口 | P-1 是关注级诊断事件，不是严重事故报警。 |
| 1:00-3:00 | 专业诊断与证据链 | 趋势、阈值、频谱、相位支撑疑似不对中。 |
| 3:00-4:30 | 专家复核与知识命中 | AI 给建议，专家确认，知识库给依据。 |
| 4:30-7:00 | 处置票卡与复测反馈 | 诊断走向标准处置和复测验收。 |
| 7:00-9:00 | 报告归档与案例复用 | 第一次闭环沉淀为案例，第二次相似异常可复用。 |
| 9:00-12:00 | 边界说明和答疑 | 不接真实系统、不训练真实模型、不替代专家。 |

## 4. 页面结构与交互方案

### 4.1 页面 1：P-1 主事件入口

页面职责：

```text
默认展开 P-1 这次关注级异常事件，让观众先看到主故事，而不是先浏览平台大盘。
```

画面应包含：

| 区域 | 内容 |
| --- | --- |
| 主事件卡 | 长岭站 P-1 输油泵机组、关注级事件、当前节点、下一步动作。 |
| 一泵一档摘要 | 泵型号、电机型号、转速、转频、关键测点数量。 |
| 测点示意 | 异常测点高亮，显示测点名称和方向。 |
| 事件时间线 | 监测回放、预警生成、待诊断、待专家复核。 |
| 辅助态势 | 站场和关注事件数量只作为小号辅助信息，不占主视觉。 |

关键交互：

| 操作 | 页面反馈 |
| --- | --- |
| 点击 P-1 关注事件 | 进入专业诊断页，并带入事件 ID。 |
| 点击异常测点 | 高亮测点对应的趋势和证据摘要。 |
| 切换“素材来源”标签 | 显示 `runtime_source` 和 `basis_source`，说明运行时是结构化演示数据。 |

主持话术：

```text
我们从 P-1 这次关注级事件进入。
这里展示的是 IMS 数据中台智能运维 demo 模块内的结构化演示数据，
不是现场上传检测报告，也不是实时生产报警。
第 1 页停留不超过 1 分钟，重点是进入主事件，不做平台总览讲解。
```

### 4.2 页面 2：专业诊断与证据链

页面职责：

```text
证明疑似不对中不是黑盒结论，而是由趋势、阈值、频谱和相位共同支撑。
```

画面应包含：

| 区域 | 内容 |
| --- | --- |
| 趋势图 | 振动趋势、B 级阈值、停机值、80% 预警线、处置后回落点。 |
| 频谱卡 | 1X、2X、6X 关键峰值，突出 2X 频谱。 |
| 相位卡 | 测点组合、相位差、相关性。 |
| 诊断结果卡 | 疑似不对中、关注级、证据标签、建议动作。 |
| 人工边界提示 | 专家确认后才进入处置。 |

关键交互：

| 操作 | 页面反馈 |
| --- | --- |
| 悬停趋势异常窗口 | 显示对应测点、数值、阈值和依据来源。 |
| 点击 `2X频谱` 标签 | 高亮频谱卡和知识命中页里的专家规则。 |
| 点击 `相位差异常` 标签 | 高亮相位卡和诊断解释。 |
| 点击“提交专家复核” | 进入专家复核与知识命中页。 |

主持话术：

```text
这里的重点不是展示复杂算法，
而是让业务方看到诊断建议背后的证据链。
趋势进入关注区，频谱出现 2X 特征，相位差也接近不对中特征，
所以系统给出疑似不对中的诊断建议。
```

### 4.3 页面 3：专家复核与知识命中

页面职责：

```text
把诊断建议变成经过人工把关、有知识依据的处置入口。
```

画面应包含：

| 区域 | 内容 |
| --- | --- |
| 复核面板 | 诊断专家、复核意见、确认 / 驳回状态。 |
| 知识命中列表 | 对中作业卡、专家规则、历史案例、报告模板。 |
| 命中理由 | 建议动作=检查对中、证据标签=2X 频谱 / 相位差异常。 |
| Agent 摘要 | 处置建议、风险提示、需要现场确认的点。 |

关键交互：

| 操作 | 页面反馈 |
| --- | --- |
| 点击“确认进入处置” | 知识命中卡变为可生成处置票卡。 |
| 点击作业卡 | 展开角色、许可、工具、步骤和验收项。 |
| 点击专家规则 | 展示规则解释和证据标签匹配关系。 |
| 点击历史案例 | 展示相似标签，不把历史案例讲成同一事件。 |

主持话术：

```text
AI 不直接替专家决定处置。
专家确认后，知识库才把对中作业卡、专家规则、历史案例和报告模板组合成可执行依据。
```

### 4.4 页面 4：处置票卡与复测反馈

页面职责：

```text
证明诊断结果可以进入标准化处置，并通过现场反馈和复测形成闭环。
```

画面应包含：

| 区域 | 内容 |
| --- | --- |
| 处置步骤条 | 草稿生成、处置确认、现场执行、复测验收、关闭。 |
| 票卡草稿 | 角色、许可/JSA 字段、工具、步骤、注意事项。 |
| 现场反馈 | 调整记录、复测数据、验收结论、确认人。 |
| 前后对比 | 处置前振动、处置后振动、状态恢复。 |

关键交互：

| 操作 | 页面反馈 |
| --- | --- |
| 点击“生成票卡草稿” | 根据对中作业卡填充标准步骤。 |
| 点击“录入现场反馈” | 展示调整记录和复测数据。 |
| 点击“确认验收通过” | 步骤条进入报告草稿节点。 |
| 点击“查看生产边界” | 提示不宣称真实 HSE 办票或供应链联动。 |

主持话术：

```text
这里生成的是 IMS 模块内的演示态处置票卡，
它说明诊断建议如何转成标准作业步骤。
真实 HSE 办票、派工审批和供应链联动不属于首版 demo 承诺。
```

### 4.5 页面 5：报告归档与案例复用

页面职责：

```text
收束业务价值：第一次闭环不是停在报告，而是变成下次可命中的知识。
```

画面应包含：

| 区域 | 内容 |
| --- | --- |
| 报告预览 | 事件概况、设备信息、诊断依据、处置过程、复测验收、经验总结。 |
| 入库卡 | P-1 不对中处置案例、标签、证据引用、复用建议。 |
| P-2 复用验证 | 第二台相似异常、相似证据标签、命中 P-1 案例。 |
| 复用建议 | 优先检查对中，调取对中作业卡，仍需专家复核。 |

关键交互：

| 操作 | 页面反馈 |
| --- | --- |
| 点击“生成报告草稿” | 从事件、诊断、票卡和反馈汇总报告段落。 |
| 点击“提交知识审核” | P-1 案例进入待审核状态。 |
| 点击“知识审核通过” | P-1 案例状态变为可复用，并写入审核确认。 |
| 点击“模拟 P-2 相似异常” | 展示 P-2 命中 P-1 案例。 |
| 点击命中理由 | 展示 `2X频谱`、`相位差异常`、`基础振动偏大` 的相似依据。 |

主持话术：

```text
第一次异常闭环后，系统不只是生成一份报告。
它把诊断证据、处置步骤、复测结果和专家意见沉淀为案例。
当第二台同类泵出现相似证据标签时，系统可以命中 P-1 案例并推荐复用路径。
```

## 5. 现有素材挂载方式

素材只用于构造结构化演示数据和页面表达，不作为 demo 现场上传输入。

| 素材 | 页面挂载 | 表达方式 |
| --- | --- | --- |
| P1 检测报告 | 页面 1、页面 2 | 设备信息、测点、趋势、频谱、相位、诊断样例。 |
| P1 对中作业卡 | 页面 3、页面 4 | 作业卡命中、角色、许可、工具、步骤、验收项。 |
| IMS 单元模型和维护表 | 页面 1、页面 4 | 一泵一档、维护记录、IMS 模块字段参考。 |
| 历史异常报告 | 页面 3、页面 5 | 历史案例、报告段落、知识库样例。 |
| 设备图和点位图 | 页面 1、页面 2 | 测点示意、异常测点高亮、现场感。 |
| 参赛申报材料 | 全局 | 三级体系、业务价值、推广口径。 |

## 6. 数据准备格式

开发前建议先冻结一个 `demo 数据包`，至少包含：

```text
assets
measurement_points
threshold_rules
telemetry_series
spectrum_features
phase_features
warning_events
diagnosis_runs
knowledge_items
knowledge_hits
work_orders
field_feedback
reports
case_entries
reuse_scenarios
```

字段细节、顶层集合和状态枚举以 [../../v1/demo-研发基准/05-结构化数据契约.md](../../v1/demo-研发基准/05-结构化数据契约.md) 为唯一事实来源。页面不要各自造字段，避免后续开发时出现同一事实多处维护。

## 7. 演示成熟度里程碑

| 阶段 | 完成标准 |
| --- | --- |
| 阶段 0：路线冻结 | 5 页页面名、P-1 主线、P-2 复用样例、边界口径确认。 |
| 阶段 1：静态走查 | 每页能展示主讲点，页面之间能按路线跳转。 |
| 阶段 2：数据挂载 | 页面读取同一份结构化演示数据，来源标签可解释。 |
| 阶段 3：闭环联动 | 专家确认、票卡生成、反馈确认、报告入库、P-2 复用状态能联动。 |
| 阶段 4：彩排交付 | 主持词、页面状态、截图素材、边界问答全部冻结。 |

## 8. 当前需要确认的事项

| 编号 | 事项 | 默认处理 |
| --- | --- | --- |
| Q1 | P-1 是否作为唯一首次闭环主线 | 默认是。 |
| Q2 | P-2 是否作为复用验证样例 | 默认是演示构造样例。 |
| Q3 | 处置后复测数据是否有真实或脱敏样例 | 没有则用演示构造并标注。 |
| Q4 | 报告模板是否采用六段式 | 默认采用六段式维修报告草稿。 |
| Q5 | 对中作业卡是否可作为标准模板卡 | 默认作为模板卡，不宣称正式适配。 |
